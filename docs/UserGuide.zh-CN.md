# TimingShow 用户手册

> 版本：1.9.3　|　适用游戏：*A Dance of Fire and Ice*（冰与火之舞）　|　许可：MIT

TimingShow 是一个面向《冰与火之舞》的 **Timing 信息提示模组**。它把你每一次击打的偏差（是打早了还是打晚了、偏差多少毫秒）、稳定性、完美率等信息，实时、可自定义地显示在游戏画面上；同时可以把这一局的每一次击打记录下来，供事后分析和长期练习复盘使用。

本手册面向**使用者**，逐项说明模组能做什么、每个开关的实际效果、以及遇到问题时怎么排查。

> **如果你是开发者**（想编译、改代码、接入新判定，或者只是想搞清楚它到底 patch 了游戏哪些函数），这份文档不会给你需要的东西。请直接看[《开发者指南》](DeveloperGuide.zh-CN.md)（[English](DeveloperGuide.en.md)）。

## 1. 这是什么

### 1.1 解决的问题

游戏本身只在完美时给出"Perfect"一类判定文字，不会告诉你**偏了多少毫秒**。对于想提高准确度的玩家来说，"这一下到底早了 3ms 还是晚了 30ms"才是可操作的信息。TimingShow 把游戏内部已经算出来、但没有显示给你的击打偏差值暴露出来，并提供多种呈现方式：

| 能力 | 说明 |
|---|---|
| 实时数值 | 单次偏差、平均值、UR（不稳定度）、Perfect 比例，可显示在 HUD / 标题 / 判定文字上 |
| 趋势可视化 | 游戏内 XACC 折线图、Timing 散点图，随时看到自己的状态曲线 |
| 复盘数据 | 把每一次击打写入日志文件，事后用图表或网页工具分析 |
| 内置分析器 | 日志窗口内含 9 种统计视图（分布、滑动均值、自相关、连击热力条等） |
| 关卡编辑器辅助 | 打完一局回到编辑器，可在轨道上看到本局的每一个击打点 |
| 本地多人 | 1–4 人同屏 coop 时，逐玩家统计与配色 |

### 1.2 支持的版本

- 同时支持 **旧版判定系统**（`HitMargin` 枚举中没有 `XPerfect` / `PerfectMinus` / `PerfectPlus` 的游戏版本）与 **3.4.0 及以后的新判定系统**。
- 模组会自己识别当前游戏版本，并自动切换算法与显示的判定种类，不需要你手动选择。识别结果会写入日志：`Detected version: ...`。
- 如果提示 `Unrecognized HitMargin enum version`，说明游戏的判定枚举发生了模组尚未适配的改动，此时数据功能可能不准确，请更新模组。

### 1.3 两种加载器

模组有两条独立的安装形态：

- **UnityModManager（UMM）**：设置界面是 UMM 窗口里的一页。
- **MelonLoader（Melon）**：设置界面是模组自己绘制的独立窗口，默认按 `F9` 呼出。

功能完全一致，**二选一安装，不要同时装**（原因见 [FAQ](#13-常见问题faq)）。

## 2. 安装与卸载

### 2.1 前置条件

- 正版《冰与火之舞》。
- 已安装 [UnityModManager](https://www.nexusmods.com/site/mods/21)（以下简称 UMM）**或** [MelonLoader](https://melonwiki.xyz/)（以下简称 Melon）。
- 下载发布包 `TimingShow.zip`（GitHub Releases，固定文件名）。

### 2.2 用 UnityModManager 安装

1. 确认 UMM 已对该游戏完成过一次安装（游戏目录下出现 `Mods` 文件夹）。
2. 用 UMM 的 **Install Mod** 直接选择 `TimingShow.zip`；
   或者手动词 zip 内的 4 个文件解压到：

   ```
   <游戏目录>\Mods\TimingShow\
       Info.json
       TimingShow.Loader.UMM.dll
       TimingShow.dll
       lang.json
   ```

   > 注意是 `Mods\TimingShow\` 这个子文件夹，不是直接扔进 `Mods\`。

3. 进游戏，UMM 的模组列表里会出现 **TimingShow**，勾选启用。
4. 打开 UMM 设置窗口（默认 `Ctrl+F10`），在左侧选中 TimingShow，右侧就是本模组的设置页。

### 2.3 用 MelonLoader 安装

1. 确认 Melon 已为该游戏完成安装，且**首次运行过游戏**（Melon 会在首次启动时生成所需目录）。
2. 把 zip 里的这 3 个文件**平铺**到：

   ```
   <游戏目录>\Mods\
       TimingShow.Loader.Melon.dll
       TimingShow.dll
       lang.json
   ```

   `Info.json` 是 UMM 专用，Melon 下不需要（放了也无害）。

3. 进游戏，按 **F9** 呼出设置窗口。

### 2.4 卸载

- UMM：在 UMM 里卸载该模组，或删除 `<游戏目录>\Mods\TimingShow\` 整个文件夹。
- Melon：删除 `Mods\TimingShow.Loader.Melon.dll`、`Mods\TimingShow.dll`、`Mods\lang.json`（如果别的模组也用 `lang.json`，请只删属于本模组的那个）。
- 卸载后如果想彻底清理，可一并删除：
  - `<游戏目录>\Mods\TimingShow\`（设置、日志、缓存的默认位置）
  - `%TEMP%\TimingShow\`（内嵌字体解压缓存，会自行重建）

> ⚠️ **不要同时安装 UMM 版和 Melon 版**。两套加载器各自会注册一整套游戏钩子，结果是 HUD 与统计都被绘制/累加两次（数字跳变、闪烁、日志重复写入）。如果切换加载器，请先完整移除另一套。

### 2.5 打开与保存设置

| 加载器 | 呼出设置 | 保存 |
|---|---|---|
| UMM | `Ctrl+F10` → 选中 TimingShow | 点击 UMM 的 **Save** 按钮（`OnSaveGUI`） |
| Melon | `F9`（可在设置里改键） | 窗口底部 **保存并关闭** 按钮；退出游戏时也会自动保存 |

**设置不会自动保存**：改完必须按上面的方式保存，否则进程被强制结束时所有改动都会丢失。

## 3. 五分钟上手

第一次使用建议按下面的顺序配置，能立刻看到效果：

1. **选语言**：设置页最顶部三个按钮 —— `简体中文` / `English` / `한국어`。
2. **打开 Timing HUD**：勾选 `显示 Timing HUD`。回到游戏随便打两下，屏幕中央会出现 `Timing - 12.3ms` 之类的文字。
3. **调位置**：展开该项，拖 `X轴偏移` / `Y轴偏移` 滑块（范围 −0.5 ~ 0.5，原点在屏幕中心，Y 正方向朝上）。
4. **想要更多信息**：依次勾选 `显示平均偏移 HUD`、`显示 UR HUD`、`显示 Ratio HUD`。它们默认在 Timing 下方依次排开。
5. **看得更直观**：勾选 `显示 Timing 散点图`。游玩中每一个点代表一次击打，绿色带是 Perfect 窗口，蓝色带是 XPerfect 窗口。
6. **开始留档**：勾选 `启用 Timing 记录`。之后每打完一局，日志目录里就会多一个文件。
7. **复盘**：设置页往下找到 `日志列表`，展开，点某一行的 **查看分析**，会弹出内置图表窗口。

## 4. 游戏内数值显示

### 4.1 四个数值 HUD

四个 HUD 各占屏幕上一行文本，互不影响，可以任意组合开关。

| HUD | 开关项 | 显示内容 | 含义 |
|---|---|---|---|
| Timing | 显示 Timing HUD | 最近一次击打的偏差 | 例 `Timing - 12.3ms`：正值表示**晚了**，负值表示**早了** |
| Avg | 显示平均偏移 HUD | 本局至今偏差的算术平均 | 例 `Avg - 8.4ms`：整体系统性偏晚 |
| UR | 显示 UR HUD | 本局的不稳定度 | 数值越小越稳定；`UR = 标准差 × 10` |
| Ratio | 显示 Ratio HUD | 判定比例 | 例 `Ratio - 12.5:1`，口径可切换（见下） |

**关于 UR**：Unstable Rate 借用 osu! 的定义，`UR = 标准差 × 10`。它衡量的是"稳定性"而不是"准确度"——一个总是早 10ms 但每次都很一致的玩家，Avg 很差不代表 UR 很差。这是练习时最值得盯的指标之一。

**关于 Ratio 的三种口径**（设置里的 `统计口径` 三个按钮）：

| 口径 | 分子 / 分母 |
|---|---|
| 完美（默认） | 完美判定次数 / 非完美判定次数 |
| +-完美 | Perfect 家族（含 Perfect−、Perfect+、Early/Late Perfect 等） / 其它 |
| X完美 | XPerfect 次数 / 其它 |

分母为 0 时显示 `infinity`；总数为 0 时显示 `0`。

#### 通用显示选项

四个 HUD 共用同一组控件：

| 控件 | 说明 |
|---|---|
| `显示格式` | 自由文本，`{0}` 会被替换为数值。默认 `Timing - {0}ms` / `Avg - {0}ms` / `UR - {0}` / `Ratio - {0}:1`。单位可写在格式串里，也可以不写 |
| `小数位数` | 0–5 位 |
| `X轴偏移` / `Y轴偏移` | −0.5 ~ 0.5，**相对屏幕中心的比例**，+X 向右、+Y 向上 |
| `缩放大小` | 0.2 ~ 3.0，基准字号为 `24 × 缩放` |
| `加粗文字` | 加粗 |
| `对齐方式` | 左 / 中 / 右 |
| `使用角度` | 显示角度偏差（`°`）而不是时间偏差（`ms`）。角度是游戏内部真正使用的量，时间值是由角度、BPM、曲速换算出来的 |
| `跟随判定改变颜色` | 文字颜色跟随本次判定（完美=绿、稍快/稍慢=黄、太快/太慢=橙红…） |
| `启用 XPerfect` | 仅在旧判定版本下出现。开启后完美家族中属于 XPerfect 的击打会用专属颜色 |
| `命中时跳动` | 每次数值变化时做一次 500ms 的放大回弹（峰值 +28%） |
| `使用自定义字体` / `字体:` | 选择一个 `.ttf` / `.otf` 文件作为 HUD 字体。选完自动勾选开关 |
| `多人时按玩家分别显示` | Coop 下每个玩家一行（详见第 6 节） |

> **格式串写错了会怎样？** 模组会捕获异常并把该 HUD 降级为只显示裸数值，不会崩游戏。但格式串会被标记为"坏格式"，修改后需要**重开游戏**才恢复。

### 4.2 替换歌曲标题

勾选 `替换标题` 后，游戏中左上角的**曲名文字**会被替换成实时数值。

| 选项 | 说明 |
|---|---|
| `小数位数` | 标题数值精度 |
| `字体大小` | 相对原字号的百分比，100 表示不改变 |
| `跟随判定改变颜色` | 数值按判定着色 |
| `启用 XPerfect` | 旧版本下区分 XPerfect 颜色 |
| `使用角度` | 显示角度而非毫秒 |
| `命中时跳动` | 命中时标题放大回弹 |

这一项的实用价值在于：标题位置天然醒目且不挡谱面，很适合只想要"一个数字"的极简配置。

### 4.3 替换判定文字（星球）

勾选 `替换判定显示` 后，击打时从星球位置弹出的那行判定文字（`Perfect` / `Early` 之类）会被替换成偏差数值。

> ⚠️ 该项**需要重进编辑器或重开一局**才完全生效（游戏会缓存判定文本组件）。标签上已注明"需重进编辑器"。如果不想每次手动重进而开启了 `自动重载编辑器`，模组会在你切换该选项时自动重启当前关卡。

| 选项 | 说明 |
|---|---|
| `小数位数` | 数值精度 |
| `字体大小` | 相对百分比 |
| `使用角度` | 角度 / 毫秒 |
| `启用 XPerfect` | 旧版本下区分 XPerfect 颜色 |
| `替换设置`（子折叠） | 选择**哪些判定**显示数字，其余判定保持原样 |

`替换设置` 里的 14 项：`提前!!`、`太快!`、`稍快`、`完美`、`完美−`、`完美+`、`X完美`、`稍慢`、`太慢!`、`太慢!!`、`多次按键!`、`多次按键`、`失误...`、`按太快!!!`、`自动播放`。

全部默认开启（`自动播放` 默认关闭）。常见用法是：只留 `完美` 系列关掉，改成显示数字；失误类保持原样，这样一眼能区分"是我打偏了"还是"我打漏了"。

> 说明：不同游戏版本可用的判定种类不同。`完美−` 只在 3.4+ 出现，`完美` 只在旧版本出现，`X完美` / `完美+` 只在游戏原生支持 XPerfect 时出现。模组会自动隐藏用不到的项。

### 4.4 死亡页面

勾选 `在玩家死亡时显示` 后，死亡时屏幕中间那行"Try calibrating…"位置会显示本局统计。

| 选项 | 说明 |
|---|---|
| `小数位数` | 各项数值精度 |
| `显示平均偏移` / `显示 UR` / `显示 XACC` / `显示 Ratio` | 四类数据的开关 |
| `字体大小` | 相对百分比 |

一行大概是这个样子（Coop 下每人一行）：

```
Avg 8.42ms    UR 96.315    XACC: 98.7421%    Ratio: 12.5:1
```

注意 `XACC` 这一项取的是游戏内部的加权准确率（`percentXAcc`），与 [5.1](#51-xacc-折线图) 里折线图的算法一致。

### 4.5 通关结算页

勾选 `在结算界面显示` 后，通关结算文字里会追加本局统计。

| 选项 | 说明 |
|---|---|
| `小数位数` | 精度 |
| `显示平均偏移` / `显示 UR` / `显示 Ratio` | 三类数据（结算页没有 XACC 项） |
| `结算页每页显示全员统计` | Coop 专用：结算页是逐玩家翻页的。开启则每一页都追加**所有人**的统计行；关闭则每页只显示当前页玩家自己的 |
| `字体大小` | 相对百分比 |

## 5. 图表：XACC 折线图与 Timing 散点图

两个图表都叠加在游戏画面上，位置、大小、颜色、字体全部可调，并且**默认不拦截鼠标**，不影响你正常游玩。

### 5.1 XACC 折线图

勾选 `显示 XACC 折线图` 后，屏幕上出现一条曲线，横轴是击打次数，纵轴是 XACC（加权准确率，0–100%）。

| 选项 | 说明 |
|---|---|
| `仅在死亡/通关时显示` | 游玩中隐藏，只在结束时显示 |
| `最大采样点数` | 只保留最近 N 个点（默认 250），游玩中表现为向左滚动的尾窗 |
| `X轴偏移` / `Y轴偏移` | 0–1 的屏幕比例，**Y 从屏幕顶部往下量**（与文本 HUD 的方向相反） |
| `图形宽度` / `图形高度` | 像素尺寸 |
| `缩放大小` | 内部字号与线宽缩放 |
| `显示边框` | 画外框 |
| `背景颜色` / `折线颜色` / `网格刻度颜色` / `坐标轴文字颜色` / `XACC 数值颜色` / `边框颜色` | 六组颜色 |
| `使用自定义字体` / `字体:` | 图表内文字字体 |
| `Show Performance Info` | 在图上叠加本帧渲染耗时（调试用，中文界面下该标签未翻译） |

曲线的数据来自游戏每次判定后累积的 `percentXAcc`，抽稀策略：**游玩中**保留最后 N 点；**结束后**如果点数超过 N，按均匀步长下采样，保证曲线形状不变。

### 5.2 Timing 散点图

勾选 `显示 Timing 散点图` 后，屏幕上出现散点图：**每一个点 = 一次击打**，纵轴是偏差（ms 或角度），横轴默认是时间。

#### 判定窗口色带

散点图最有价值的部分是背景色带，它把"哪些区间算 Perfect"直接画出来：

- 绿色半透明带 = Perfect 窗口
- 黄绿色带 = Early/Late Perfect 窗口
- 橙红色带 = 更外围的判定窗口
- 蓝色带 = XPerfect 窗口（更窄）

窗口宽度不是固定值，而是由 **BPM × 曲速 × 音高 × 难度** 换算出来的——因为游戏内部的判定是以"角度"为单位的，BPM 越高，同样的角度对应的时间就越短。

| 选项 | 说明 |
|---|---|
| `按游戏难度与BPM自动计算窗口` | 默认开启。开启时模组实时读取当前关卡的 BPM 与难度；关闭后改用下方滑块指定的固定阈值 BPM，便于对照不同 BPM 的谱面 |
| `窗口阈值BPM` | 手动模式下的换算基准（100–600） |
| `显示判定窗口色带` | 总开关 |
| `显示 XPerfect 色带` | 单独控制最内侧蓝带 |
| `Perfect / E-L Perfect / Early-Late 色带颜色` | 三段色可分别改色 |
| `XPerfect 色带颜色` | 蓝带颜色 |

#### 其它显示选项

| 选项 | 说明 |
|---|---|
| `仅在死亡/通关时显示` | 游玩中隐藏 |
| `X轴使用击打序号` | 横轴从时间改成序号（第 N 次击打），关掉自动滚动后适合静态查看 |
| `始终滚动（可能会影响性能）` | 开启后视窗每帧跟随最新点滚动。这是**唯一的持续性性能开销**来源，低配机器建议关闭 |
| `窗口采样点数` | 游玩中参与绘制的最远历史点数（默认 200） |
| `最大渲染点数` | 抽稀上限（默认 800，可调 20–8000）。超过上限时按"每像素一个桶，每桶保留最小值和最大值"的方式压缩，**尖峰不会被抹掉** |
| `点大小` | 1–12 |
| `按判定颜色着色` | 点色跟随判定；关闭则全部用统一颜色 |
| `显示 0 ms 参考线` | 画一条 `y = 0` 的参考线 |
| `显示平均值曲线` | 画出累积平均值曲线 |
| `总览图忽略离群点` | 用 Tukey 1.5×IQR 规则裁掉极端值，避免一两个离谱的点把 Y 轴拉爆 |
| `显示边框` / `边框颜色` | 外框 |
| 背景/网格/点/0 ms 线/平均值线/坐标轴文字颜色 | 七组颜色 |
| `Show Performance Info` | 调试信息 |
| `使用自定义字体` / `字体:` | — |

#### 交互

散点图在**关卡结束或暂停**时才接受鼠标（避免游玩中误触）：

| 操作 | 效果 |
|---|---|
| 拖动 | 平移视窗 |
| 滚轮 | 以鼠标位置为锚点缩放 |
| 悬停 | 显示该次击打的详情面板：时间、偏差、判定、玩家、所属楼层等 |

暂停后点击游戏画面即可操作散点图；`Hint: 拖动平移 · 滚轮缩放` 的提示会在进入可交互后显示 8 秒。

## 7. Timing 日志

### 7.1 开启记录

勾选 `启用 Timing 记录`。从**下一局开始**生效（当前局需要重开才会创建会话）。

| 选项 | 说明 |
|---|---|
| `小数位数` | 日志中数值的精度（默认 4） |
| `使用角度` | 记录角度而不是毫秒。**注意：这会让日志中的"偏差值"变成角度单位**，很多分析工具默认按毫秒理解 |
| `自动播放时也记录` | 默认不记录自动播放；开启后会一并记录 |
| `使用 JSON 日志格式` | 见下 |
| `保存路径:` | 日志目录，默认 `<游戏目录>\Mods\TimingShow\Logs` |
| `缓冲区大小 (KB)` | 写缓冲大小，默认 64。缓冲区越大，崩溃时丢失的记录越多（因为只在会话结束时 flush） |
| `打开 Logs 文件夹` | 用文件管理器打开日志目录 |

日志只在**实际打出了击打**时才产生文件——如果一局一个判定都没有（比如中途退出），文件会被自动删除，不会留下一堆空文件。

### 7.2 两种格式

| | JSON（`.json`） | 二进制（`.tlog.gz`，默认） |
|---|---|---|
| 可读性 | 纯文本，可直接查看/编辑 | 需专用工具或本模组读取 |
| 大小 | 较大（每条约 45–90 字节） | 较小（gzip 压缩，每条约 24–50 字节） |
| 兼容性 | 网页分析器、内置图表窗口都支持 | 内置图表窗口支持；网页分析器也支持（通过本地 HTTP 服务读取原始字节） |
| 结构版本 | `formatVersion: 8` | `binaryFormatVersion: 9` |

**选哪个？** 只是想长期存档、节省空间 → 二进制（默认）。想手动查看、或想用第三方脚本处理 → JSON。

> 格式是**每局独立决定**的：中途改这个开关只影响下一局。

### 7.3 文件命名

```
<时间戳>_<曲名>.json
<时间戳>_<曲名>.tlog.gz
例：1738742903_Final Destination.json
```

- 时间戳是 Unix 秒。
- 曲名中不能用于文件名的字符会被替换为 `_`。
- **同一秒内开始的两局同曲会互相覆盖**（文件名为 `Create` 模式）。正常游玩不会碰到，脚本化批量测试时需注意。

### 7.4 自动清理

勾选 `自动清理` 并设定"只保留前 N 个文件"（默认 50）。

- 触发时机：**每局结束时**。
- 排序规则跟随日志列表当前的排序方式（时间 / 大小 / 曲名）。默认按时间，保留最新的 N 个。
- 只处理日志目录**第一层**的 `.json` / `.tlog` / `.tlog.gz`，不递归。
- 正在写入的文件会被跳过。

### 7.5 日志列表

设置页里的 `日志列表` 折叠区是一个完整的日志管理器。

| 控件 | 功能 |
|---|---|
| `刷新` | 重新扫描目录 |
| `排序: 时间 / 大小 / songName` | 点击循环切换。默认按时间新→旧 |
| `搜索` | 对文件名、曲名、完整路径做子串匹配；右侧 `×` 清空 |
| 汇总 | 底部显示"共 N 个文件，占用 X MB"（按当前可见条目统计） |
| 每行的 `查看分析` | 在**内置图表窗口**中打开（见第 8 章） |
| 每行的 `打开文件` | 用系统默认程序打开 |
| 每行的 `删除` | **两段式确认**：第一次点击变红，3 秒内再点一次才真删 |
| 每行的 `Web分析页面` | 仅当启用 `Analyzer 本地服务` 时出现，见 [8.1](#81-在线分析器推荐) |

列表是虚拟滚动的，文件再多也不会卡死；但每帧最多绘制 60 行，快速滚动时可能出现空白行，这是设定内行为。

## 8. 日志分析：在线分析器与内置图表窗口

### 8.1 在线分析器（推荐）

网页版分析器：[https://sleepingcui.github.io/adofai_offset_analyzer](https://sleepingcui.github.io/adofai_offset_analyzer)

可以手动把日志文件拖进网页，也可以在游戏里一键跳转：

1. 展开 `高级功能`，勾选 `启用 Analyzer 本地服务`。
2. 可选：设置 `服务端口 (0=随机)` 与 `服务超时 (秒)`（默认 0 = 系统分配，60 秒超时）。
3. 在日志列表某一行点击 **Web分析页面**。

背后的机制：模组在本机 `127.0.0.1` 上临时起一个只读的 HTTP 服务，生成一次性 token 的 URL，然后把浏览器指向分析器页面。分析器页面通过这个 URL 把日志取走。超时后服务自动关闭。

> 安全说明：服务只监听回环地址（`127.0.0.1`），只接受带一次性 token 的请求，只对该 token 对应的单个文件返回内容。不会把任何数据上传到模组作者或第三方服务器。
>
> 已知小问题：浏览器有时会先发一个 `OPTIONS` 预检请求，而服务只接受一次连接，可能导致首次打开失败——再点一次"Web分析页面"即可。

### 8.2 内置日志图表窗口

在日志列表点击 **查看分析**，会读取整份日志并弹出一个图表窗口。它不依赖网络，适合离线复盘。

#### 窗口基础操作

| 操作 | 方式 |
|---|---|
| 拖动窗口 | 按住标题栏拖动 |
| 缩放窗口 | 拖右下角 |
| 关闭 | 标题栏右侧 `✕`（`Escape` 只关下拉菜单，不关窗口） |
| 切换视图 | 顶部下拉菜单（9 个视图） |
| 只看某个玩家 | Coop 下顶部有玩家下拉菜单；散点视图也可直接点图例色块 |
| 打开设置面板 | 顶部齿轮按钮，里面有 `基础` / `颜色` 两页 |
| 窗口尺寸记忆 | 每次缩放结束自动保存，下次打开沿用 |

窗口内的 `界面缩放`（0.75–3.0）会等比缩放整个窗口的字号和行高，高分辨率屏幕上建议调大到 1.5 以上。

#### 九个视图

| 视图 | 看什么 | 对你的用处 |
|---|---|---|
| **概览**（默认） | 四张卡片（总命中 / 最大连击 / UR / Ratio）+ XACC 大字 + 判定分布条形 + 文件元信息 | 一进来先看这页，快速建立对整局的印象 |
| **散点图** | 每次击打的偏差，带判定色带与玩家图例 | 看整体走势、有没有系统性偏移 |
| **分布图** | 偏差直方图 + 正态拟合曲线 + 均值线与 ±σ 线 | 看你的误差是不是"随机"的。理想情况下应接近钟形曲线并中心对齐 0 |
| **XACC 曲线** | 累计加权准确率随击打序号的变化，多玩家多条曲线 | 看这局是否越打越好/越打越崩 |
| **Δ 分布** | 相邻两次击打之差（本次 − 上次）的直方图 | 看"调整是否有规律"。若 Δ 呈明显偏态，说明你在做系统性的追赶修正 |
| **滑动均值** | 滑动窗口均值曲线 + ±1σ 带，窗口大小 5–500 可调 | 看趋势而不被单次抖动干扰。轨道图上方的滑块可实时改窗口 |
| **偏移关系** | 上一次偏差 vs 本次偏差的散点（带 y=x 对角线与相关系数） | 判断"误差是否可预测"。相关系数为负说明你在**过度修正**（上次早、这次就打成晚）；为正说明误差在**延续** |
| **连击热力条** | 用颜色表示连击长度的条带，灰色段是断连 | 一眼看到断连集中在哪里、最长连击出现在什么位置 |
| **自相关** | lag 1–50 的自相关系数柱 + 95% 置信带 | 更严格的周期性检测。超出置信带的 lag 说明存在周期性失误（例如某种特定节奏型） |

#### 散点范围筛选

散点视图左上角有一行 **范围筛选**：`[最小] ~ [最大]` 两个输入框，单位是 `ms`（角度日志为 `°`）。

- 点击输入框直接键入数字，支持负号和小数；按 `Enter`、`Escape` 或点窗口其它位置结束输入。
- 留空表示该侧不限制。两个框都留空即不过滤。
- 范围外的点不再绘制，均值线和自动 Y 轴也只按范围内的点计算；右侧实时显示「范围内 N 个点」。
- 点 **重置** 清空两个输入框。
- 范围只在当前窗口内有效，切换视图不会丢失，关闭窗口后重置。

#### 统计面板

窗口左侧（或底部）会按当前视图显示四行统计：

- 散点页：总命中、UR、Ratio、XACC
- 分布页：均值、标准差、偏度、超额峰度
- Δ 页：配对数量、平均绝对差、中位绝对差、平均差
- 滑动页：前段均值、后段均值、漂移量（正 = 越打越晚）
- 偏移关系页：配对数量、相关系数、判定结论（过度修正 / 偏差延续 / 相互独立）
- 连击页：连击段数、最长连击、平均连击
- 自相关页：样本数、lag-1 系数、最显著 lag、对应系数

#### 设置面板

齿轮按钮打开，改完需要点 **应用**（`Apply`）才会生效并保存：

**基础页**：界面缩放、圆角强度、点大小、最大渲染点数（对数滑块）、忽略离群点、X 轴用序号、按判定着色、区分玩家、显示 0ms 线、显示均值线、显示网格、显示判定色带、显示 XPerfect 色带、窗口阈值 BPM、使用自定义字体。

**颜色页**：10 个色槽（背景/网格/散点/0ms 线/均值线/坐标轴文字/Perfect 带/E-L 带/Early-Late 带/XP 带），每槽有 R/G/B 三个滑块，右侧按钮只重置 RGB、保留透明度。底部实时预览十六进制值与 alpha。

### 8.3 该怎么选

| 需求 | 建议 |
|---|---|
| 快速看一眼整体表现 | 内置窗口 → 概览 |
| 深度统计、导出、对比多次记录 | 网页分析器（功能更全，可保存报告） |
| 没有网络 / 想离线 | 内置窗口 |
| 只想确认某个裁决是否记录正确 | 直接打开 `.json` 日志 |

### 8.4 不开日志也能看：上次击打报告

把「启用 Timing 记录」关掉时，上面两条路都用不了——没有文件可以分析。这时候用**报告窗口**：

1. 在设置面板底部把「击打报告按键」设成某个键（默认 `F10`，`None` 表示不用快捷键）。
2. 打完一局：通关、失败、被弹回关卡编辑器都算。
3. 按下这个键就弹出窗口，内容和「内置日志图表窗口」完全一样（9 个视图、按玩家筛选、统计面板），只是数据来自内存而不是文件；再按一次关闭。

整局进行中数据一直留在内存里，所以日志关着也不影响。它是**单局快照**：开始下一局时上一份不会被立刻清掉，直到新的一局结束后被覆盖。设置面板里那个「查看上次击打报告」按钮作用相同，没有可用数据时会置灰。

## 9. 关卡编辑器击打点

这是 1.9.x 加入的功能：**打完一局回到关卡编辑器后，在轨道上显示本局的每一个击打点**。

### 使用流程

1. 在编辑器里正常试玩一局（通关、死亡、或主动退出回编辑器都行）。
2. 回到编辑器后，模组会把这一局的击打点绘制到对应的楼层位置上。
3. 点的大小、颜色、悬停详情都可配置。

### 显示内容

- 点的颜色 = 判定颜色（与 HUD 一致）。
- 点的**位置**锚定在命中楼层上，并向"早了/晚了"的方向做角度偏移——偏移量由 `角度偏移倍率` 控制（0 = 全部叠在楼层正中，1 = 按实际角度偏移）。
- 鼠标悬停在某个点上会显示详情：玩家、偏差、角度、判定、BPM × 曲速、楼层编号。楼层编号带 `~` 前缀表示该编号是模组估算的（旧版游戏拿不到精确楼层）。

### 相关设置

| 选项 | 说明 |
|---|---|
| `显示编辑器击打点` | 总开关 |
| `点大小` | 1–100 像素（按 100% 缩放计），圆圈随编辑器缩放等比放大 / 缩小 |
| `角度偏移倍率` | 0–3，见上 |
| `显示悬停详情` | 关闭后只有点，没有 tooltip |
| `清除击打点` | 立即清掉当前显示的点 |
| `导入日志并显示` | 从日志文件（`.json` / `.tlog` / `.tlog.gz`）导入历史记录并显示。要求该日志对应的关卡与当前编辑的关卡一致 |

### 限制

- **只对"刚刚结束的这一局"生效**（数据存在内存里）。离开关卡、开始下一局、或禁用模组都会清除。
- 导入历史日志需要日志格式包含楼层信息：JSON 需 v8 及以上，二进制需 v9 及以上。旧日志会提示"日志中没有任何楼层信息"。
- 若日志是在**当前编辑关卡之外**录的，会提示"日志与当前编辑关卡不匹配"。

## 10. XPerfect 支持与两种模式

XPerfect 指的是**比 Perfect 更精确**的那一档判定。

### 游戏原生支持时（3.4.0+）

游戏判定枚举自带 `XPerfect`，模组直接使用游戏给出的结果，无需任何额外配置。此时设置里不会出现 `启用 XPerfect` 与 `开启 XPerfect Hook 模式` 选项（因为不需要）。

### 旧版本游戏

旧版本的判定枚举里没有 XPerfect，模组提供两条路径：

**路径 A：内置算法（默认）**

模组按 XPerfect 模组（[8100print/XPerfect](https://github.com/8100print/XPerfect)，MIT）的公开算法，把每次判定的偏差与该 BPM 下的边界值比较。边界值随 BPM 变化，且有 15° 的下限保护。

适用：没装 XPerfect 模组，或想用纯算法结果做一致性对照。

**路径 B：Hook 模式**

勾选 `高级功能` → `开启 XPerfect Hook 模式`。模组会尝试反射挂钩已安装的 XPerfect 模组，直接读取它给出的判定结果。

- 右侧会显示状态：绿色 = 挂钩成功；红色 = 失败（附原因）；蓝色 = 不适用（当前游戏版本不需要）。
- 需要 XPerfect 模组已加载，且本模组在其之后加载（`Info.json` 里已配置 `LoadAfter: XPerfect`）。
- 找不到 XPerfect 模组时会记日志并保持失败状态，不会反复重试。

> 两条路径在极端情况下可能给出不同结果（尤其是判定的边界点上）。如果做数据对比，建议固定一种模式。

## 13. 常见问题（FAQ）

**Q：安装后游戏里什么都没出现？**
先确认模组已被加载：UMM 列表里勾选了 TimingShow，或 Melon 控制台出现 TimingShow 的加载信息。然后确认你要显示的项目**已经勾选**——所有 HUD 默认都是关闭的。

**Q：数字一直是 `--`？**
只有 Coop 模式下、且该玩家还没击打过，才会显示 `--`。单机出现 `--` 说明玩家归属解析异常，请把日志发给作者。

**Q：改了设置但没有生效？**
必须**保存**：UMM 点 Save，Melon 点"保存并关闭"。另外注意：日志格式/目录、缓冲区等设置只对**下一局**生效。

**Q：换了字体但游戏里还是旧字形？**
字体是编译时打包进 DLL 的，改字体资源需要**完整重建**（普通的增量构建会跳过）。如果你是在开发环境里遇到这个问题，用 `/t:Rebuild`。

**Q：同时装了 UMM 版和 Melon 版会怎样？**
HUD 会重叠绘制、统计会双倍累加、日志会重复写入。请只保留一套。

**Q：日志文件为什么没生成？**
三个常见原因：① 没勾 `启用 Timing 记录`；② 这一局一个击打都没有（空会话会被删除）；③ 这一局是自动播放，而 `自动播放时也记录` 没开。

**Q：日志报表里的数值和游戏里看到的不一样？**
先确认 `使用角度` 是否开启——开启后日志存的是角度而不是毫秒。另外判定字段的数值编码在不同游戏版本下含义不同（旧版本 `Perfect` 和新版本 `Perfect−` 使用同一个编码），分析时要结合日志头部的 `hitMarginVersion` 判断。

**Q：散点图/图表窗口的鼠标不响应？**
游戏内散点图只在**暂停或关卡结束后**接受鼠标。日志图表窗口则始终可交互，但如果你把设置面板打开了，散点图的交互会被临时挂起。

**Q：`Web分析页面` 按钮不见了？**
它只在启用 `Analyzer 本地服务` 时出现。

**Q：点了 `Web分析页面` 浏览器报错？**
可能是浏览器的 `OPTIONS` 预检请求占用了唯一的一次连接，再点一次即可。也可能是端口被占用，换一个端口或保持 0（随机）。

**Q：`中文界面里有一堆英文`？**
Debug 分组、两个 `Show Performance Info` 开关、以及 UR 标签尚未翻译，属于已知缺口，不影响功能。

**Q：`Unrecognized HitMargin enum version` 是什么？**
游戏更新了判定枚举，而模组尚未适配。此时数值可能不准，请等待模组更新。

**Q：怎么反馈 bug？**
请附上：① `Player.log`；② 出问题那一局的日志文件（或截图）；③ 使用的游戏版本、加载器（UMM/Melon）与模组版本。

## 14. 已知限制

**功能层面**

- `替换判定显示` 修改的是游戏中唯一的判定文本组件，因此**需要重进编辑器/重开一局**才能完全生效。
- 结算页**没有 XACC 项**（与死亡页不对称），这是设计上的取舍。
- 游戏内散点图**不显示玩家图例、也不能按玩家过滤**（只有日志图表窗口里的散点视图支持），但 Coop 下点色仍按玩家区分。
- 编辑器击打点只保存"刚结束的这一局"到内存，不做跨局历史浏览。
- 标题替换只修改共享的曲名文本，Coop 下无法逐玩家分列（会拼成一行）。

**数值层面**

- UR 与标准差使用**总体方差**（除以 n），与某些统计软件默认的样本方差（除以 n−1）略有差异。
- XACC 在模组里有三种口径（游戏原生 `percentXAcc`、日志 XACC 视图的逐判型加权、概览页的分组加权），数值可能不同。做严格对比时请说明用的是哪一个。
- 旧版本判定系统下，XPerfect 判定依赖外部模组或本地算法，两者在边界点可能不一致。
- 早期版本（判定枚举无 `XPerfect`）的日志中，判定编码 3 同时表示 `Perfect` 和 `Perfect−`，需结合版本字段解读。

**性能层面**

- `始终滚动` 会让散点图**每帧重绘**，是唯一持续性的性能开销。
- `最大渲染点数` 设有硬上限（受 Unity UGUI 65535 顶点约束，实际有效上限 6540 点）；超过会被静默截断，并且圆点会退化为多边形。
- 日志列表每帧最多绘制 60 行，快速滚动时可能出现空白行。
- 解析大日志文件在后台线程进行，解析期间界面只显示"正在读取…"提示，不可取消。

**界面层面**

- 数值输入框（如"缓冲区大小"）采用"非法即回退默认值"的处理：无法逐位输入（清空后立刻打不进去数字），建议整体选中后覆盖输入。
- 设置只在退出/保存时落盘，且不是原子写入。强制结束进程可能丢失改动或损坏 `Settings.json`（损坏后会回退默认值）。
- 图表窗口没有做 DPI 适配，高分辨率屏幕需要手动调大 `界面缩放`。
